# LiChU. 5분 발표 스크립트

## 0:00–0:30 문제
회사에서 Copilot이나 Figma가 필요할 때 누구에게 요청하시나요? 메일과 메신저로 요청하면 남은 좌석을 알기 어렵고, 사용이 끝나도 라이선스가 계속 점유되기 쉽습니다. 승인이나 반려 이유도 흩어집니다.

## 0:30–1:00 서비스 소개
**LiChU.는 한정된 SaaS 좌석의 신청부터 승인, 할당, 반납과 회수까지 하나의 흐름으로 관리하는 서비스입니다.** 역할은 임직원과 관리자 두 가지입니다.

## 1:00–2:30 USER Flow
[직원 계정으로 로그인 → 탐색 화면]
한 화면에서 소프트웨어 설명, 플랜, 단가와 잔여 좌석을 확인합니다. 검색과 카테고리로 필요한 도구를 찾습니다.
[사용 신청 모달]
사용 목적과 예정 기간을 입력합니다. 잔여 좌석이 없어도 신청할 수 있지만, 확보되기 전에는 승인할 수 없습니다. 이미 사용 중이거나 대기 중인 신청은 중복 신청을 막습니다.
[내 신청]
진행 상태뿐 아니라 승인·반려 사유를 확인할 수 있습니다. 대기 중에는 취소할 수 있고 기록은 지우지 않습니다.
[내 라이선스]
승인된 라이선스가 이곳에 나타납니다. 업무가 끝나면 확인 후 직접 반납하며, 즉시 좌석이 반환됩니다.

## 2:30–3:40 MASTER Flow
[관리자 대시보드]
전체, 사용 중, 잔여 좌석과 승인 대기 수를 확인합니다. 높은 사용률도 별도로 표시합니다.
[신청 관리]
신청자의 이름과 부서, 목적, 사용 기간, 현재 잔여 좌석을 보고 사유와 함께 승인하거나 반려합니다. 처리된 요청은 대기 목록에서 즉시 사라지고 이력으로 이동합니다.
[라이선스 관리 → 사용자 목록]
카드를 클릭하면 실제 사용자의 인사 정보와 할당 목적을 확인할 수 있습니다. 사유를 입력해 회수하면 이력을 유지하면서 좌석을 확보합니다. 등록과 수정도 가능하지만 현재 사용량보다 좌석을 줄일 수 없습니다.

## 3:40–4:20 ERD/API 설계
Department, User, License, Request, Assignment 다섯 Entity를 사용합니다. 승인 요청은 최대 한 개 Assignment와 연결됩니다. 좌석 사용량은 별도 컬럼이 아니라 ACTIVE Assignment 개수입니다. 승인과 할당은 같은 트랜잭션이며 PostgreSQL 행 잠금으로 마지막 좌석의 동시 승인을 막습니다. UI 행동은 실제 FastAPI와 연결되고 OpenAPI와 DBML은 구현에서 생성합니다.

## 4:20–5:00 한계 및 확장
현재 할당은 사내 관리 시스템상 사용 권한 배정입니다. 외부 SaaS 계정을 자동 발급하거나 사용량을 자동 측정하지 않습니다. 이번 범위에서는 JWT와 자체 회원가입을 사용하며 실제 기업 적용 시 SSO와 HR 연동을 먼저 검토할 수 있습니다. 이후 Vendor API 연동과 알림 등을 확장할 수 있습니다. 이번 프로젝트에서는 기능 수보다 화면, API, DB, 상태 변화의 일관성에 집중했습니다.
