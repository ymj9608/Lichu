# 제출 요구사항 정의서 정합성 확인

- 기준: 실제 API Router, Pydantic Schema, Service, ORM, Vue Router/화면, 기존 검증 기록.
- 예시: 판교5-U000-홍길동-요구사항정의서ver1.pdf의 상세 요구사항·비기능·추적성 표 구조.
- 작성자: 판교5 / P157 / 윤명진, 2026-09-08, v1.2.
- 기능 요구사항 21개와 비기능 요구사항 9개를 작성했다.
- API 23개 method/path가 실제 Router 선언과 정확히 일치함을 계약 테스트로 확인했다.
- PDF의 기능 ID 21개가 기능 정의와 추적성에 각각 1번씩 존재하고, 비기능 ID 9개가 모두 존재함을 확인했다.
- Pages에서 DOCX를 열어 native Pages 저장 및 PDF 출력을 수행했다. 총 6쪽, 표 잘림 없이 전체 요구사항·추적성 포함.
- 기존 “라이선스 삭제”는 실제 구현의 “수정·비활성화”로 정정했다.
- 자동 일일 백업, 2초 응답 보장, Edge 검증은 구현 완료로 기재하지 않았다.
- 로그아웃은 클라이언트 토큰 삭제, 검색/분류·10건 페이지는 클라이언트 처리, 좌석은 서버 집계로 구분했다.
- MASTER는 회원가입으로 생성하지 않으며 예정일 기반 자동 provisioning/회수는 없다.
- 프로필 사진 포함 회원 정보 수정과 권한 승인 기간 수정 요구사항을 추가하고 사용자 검색·기간 표시 요구사항을 실제 화면에 맞췄다.
- 기능별 공수는 참고 추정치이며 실적이나 3일 일정 확정 합계로 표시하지 않았다.
- 이전 Pages는 제출파일/원본보관/에 보존했다. v1.2 Pages·DOCX·PDF는 현재 프로젝트 구현과 일치한다.
